# Decisions

Dated decisions, many by the user's choice. Read the ones for an area before changing its behaviour or wording, and add new ones here. Do not undo one without asking.

- 2026-10-22: The app is built the way Mateen Money is: the same ground rules, three layers, sync model (one `rev` counter, soft deletes, `GET /sync?since=rev`), writing style, design principles and git rules. Mateen Money's files are copied in where HANDOVER.md section 7 says (styles.css, dom.js, idb.js, sw.js, app.js, the Worker setup and the service worker tests), never linked. Its decisions on the look carry over too: no spring or press-scale motion, a neutral raised shadow, no tab bar blur, one small-print size, segmented controls for view switches, text-style secondary buttons (its decision of 2026-10-01).
- 2026-10-22: Mateen Money's repo is `../Mateen Money` (not `../mateen-money`); it is read only. `reference/mateen-money-CLAUDE.md` is its CLAUDE.md as of today.
- 2026-10-22: Unlike Mateen Money, the Worker never works out "today", and has no time zone setting. The phone sends every date: entries carry the local date at logging, Shortcuts send the phone's date, and summary requests send the phone's timestamp with its offset.
- 2026-10-22: Unlike Mateen Money, the Worker calls an AI model: Claude Haiku 5.5 (`claude-haiku-5-5`) for sentence and photo logging (parse, then estimate for unmatched items only). The phone never calls it. A spending limit is also set in the Anthropic Console. The daily cap is below (2026-10-23).
- 2026-10-22: Food sources are Open Food Facts (barcodes and branded UK foods, with an identifying User-Agent), CoFID (imported once into D1 by `scripts/import-cofid.js`, which prints what it will import and needs `--apply`) and USDA FoodData Central. Looked-up foods are cached in D1 with `fetchedAt`.
- 2026-10-22: The app is called Mateen Foodey (the user's choice).
- 2026-10-22: Fixed mode adds back 50% of a day's exercise kcal by default, editable in Settings (the user's choice): Health's active energy tends to read high and MET figures are rough, so half errs on the side that won't disappoint.
- 2026-10-22: The accent is not Mateen Money's blue, so the two apps can be told apart at a glance (the user's choice). It keeps the blue palette's roles and contrast and isn't red or amber. A green is proposed in Stage 3, with swatches, for the user to pick.
- 2026-10-22: Body weight shows in kg by default ("72.4 kg"), with st lb as a setting (the user's choice).
- 2026-10-22: Dietary write-back to Apple Health is deferred to version two (the user's choice). Version one has no write-back Shortcut, no `writebacks` table and no `GET /day` or `POST /day/*` routes (`GET /day` only served write-back). The incoming Health Shortcut (`POST /health`: activity, steps, workouts, weight), Sync Health and the weight history import are unchanged. Version two's design is in SPEC.md, Later: each nutrient per date is claimed before writing, never retried automatically, and an unconfirmed write needs "Leave Incomplete" or "Retry Anyway" (which warns about a possible duplicate). Exactly-once delivery is not guaranteed.
- 2026-10-22: `~/Downloads/CLAUDE.md` (a generic website template: Tailwind from a CDN, web fonts, Windows Puppeteer paths) is ignored; this project's CLAUDE.md is followed instead (the user's choice).
- 2026-10-22: D1 is created in Western Europe, where the user is now (the user's choice). The user moves to the US in 2027 and to Singapore for good in 2028. Then the Worker gets `[placement]` beside the database, as in Mateen Money, so a request makes one long trip rather than one per query. Moving the database to Asia-Pacific is an export and import, if it's ever wanted.
- 2026-10-22: The Worker calls the Claude API with plain `fetch`, not the Anthropic SDK (the user's choice), so the project keeps no dependencies and `npm test` needs no install.
- 2026-10-22: The repo is `spowlf/mateen-foodey`, public like Mateen Money's (GitHub Pages needs it), pushed straight to `main`.
- 2026-10-22: Dictation is the iOS keyboard's own; the app builds no microphone feature. Barcodes are typed first; camera scanning comes later, with the decoder vendored into `vendor/` and served from our own origin.
- 2026-10-23: Every route needs the bearer token; there is no unauthenticated health check (`GET /ping` was dropped from the proposal). `PUT /:table/:id` rejects a body whose `id` differs from the URL's, so a row can never be saved under the wrong id.
- 2026-10-23: The cost guard allows 100 model calls a day, and every call counts: parse, estimate and the sentence Shortcut's (`POST /log`). Its day is the Worker's own UTC date, the one exception to "the phone decides the date". Why: it's a spending cap, not user data, so it follows the bill rather than where the phone is, and a wrong or changing phone date can't reset it. Check and increment are one atomic D1 statement (an upsert that only adds while under 100, returning the new count), so two calls at once can't both take the last one.
- 2026-10-23: The goal rate is stored only in `targets` (with the target it produced), not in settings, so there's one place for it.
- 2026-10-23: Search asks the Worker only after a pause in typing, not on every keystroke, and the Worker caches recent queries as well as the foods they found, to keep requests to Open Food Facts and USDA modest.
- 2026-10-23: The weekly review's one-tap answer is "Mark N Days Complete" (N = the reviewed week's unflagged unreviewed days, the real count), not "All 7 Complete", since some days may already be marked and flagged days are asked about one by one (see the Monday review entry below).
- 2026-10-23: Restore validates the whole backup file before writing anything (valid JSON, required fields, duplicate ids, references between foods, recipes, batches, pots and entries), then writes it in one D1 batch, which runs as one transaction. A rejected or failed restore leaves the database exactly as it was and says "Nothing changed: …".
- 2026-10-23: The weekly review is on Monday morning and covers the previous Monday to Sunday (the user's choice), unlike Mateen Money's Sunday review. The card shows on Log from Monday until completed; `reviews.id` is the Monday that starts the reviewed week. The summary Shortcut runs on Monday morning, and `GET /summary?date=` and `POST /summary { timestamp }` pick the week before the one the date falls in. "Mark N Days Complete" confirms the reviewed week's unflagged unreviewed days and shows the real count; flagged days (under 60% of their target) are asked about one by one ("Was Tuesday complete?").
- 2026-10-23: Until the maintenance estimate has its minimums, its message is built from the real state, showing each part only while it's needed: "Log 6 more complete days and add 2 more weigh-ins.", "Log 6 more complete days.", "Add 2 more weigh-ins." Once both are met, the estimate shows instead.
- 2026-10-23: A backup holds every row, deleted ones too (Mateen Money's held only live rows), so an entry whose food was later deleted still finds it and restore can check every reference.
- 2026-10-23: An entry's or batch's nutrition is stored in thousandths of a kcal and micrograms (agreed in the proposal), so logging a food never rounds; the one rounding before display is splitting a batch, with any remainder in the last portion. The trend weight is worked out from the readings each time and never stored, so it's kept as a fraction of a gram and rounded only for display.
- 2026-10-23: Small rules set in Stage 1, for the user to overturn: CoFID fibre is AOAC fibre (the UK label method), and blank when only NSP is given; "usual grams" is the last portion logged; quick add's untyped macros are unknown, not 0; meal slots start at 04:00 / 11:00 / 17:00 / 21:00, and before 04:00 is still snacks; a day exactly at 60% of its target isn't flagged ("under 60%"); each nutrient left unknown gets its own sentence ("Fibre unknown for 1 food.", then "Salt unknown for 1 food.") so two foods' gaps never read as one food's; the maintenance estimate's 150 kcal weekly cap chains back only through weeks that meet the minimums.
- 2026-10-23: Quick-log chip order (by use in the current meal slot) moves to Stage 3, since ordering saved meals needs to know which entries came from one.
- 2026-10-23: Small rules set in Stage 2, for the user to overturn: food memory (usual grams, use count, last use) updates when an entry becomes logged, new or confirmed from To check, so a Shortcut's guessed portion never becomes your usual; search lists CoFID, then Open Food Facts, then USDA, up to 10 each, best first; a food matches only when every word of the search is in its name or brand (plurals folded), and a food weighed raw never matches one listed cooked, or the other way round ("as sold" fits either); USDA search covers Foundation, SR Legacy and Survey foods, not US branded ones; a barcode is looked up again after 30 days, and the cached food is kept if Open Food Facts can't be reached.
- 2026-10-23: Open Food Facts search uses its search service (`search.openfoodfacts.org`, UK products only), since the old `cgi/search.pl` refuses country-filtered searches; barcodes use the product API (`/api/v2/product/<code>.json`). The USDA key goes in the `X-Api-Key` header, never the address.
- 2026-10-23: A food fetched again from its source refreshes your own copy (name, brand, nutrition, servings), unless you've edited it (`userEdited`).
- 2026-10-23: Every write checks that the foods, recipes, batches and pots its live rows name are saved (deleted ones count), so a backup of the data always passes restore's reference check.
- 2026-10-23: An estimate saved by logging is one of your foods, so the next sentence naming it matches it without another estimate call.
- 2026-10-23: When the day's model calls run out between the parse and the estimate, `/parse` still returns the matched items; the rest come back without a food, to search for.
- 2026-10-23: `POST /log` replies in the words that were parsed ("3 items to check: eggs, toast, flat white."), and names anything it couldn't find ("Search for haggis in the app."). Its entry ids are `shortcut:<timestamp ms>:<n>`; a retry replies "Already saved: 3 items to check." and makes no model call.
- 2026-10-23: The Worker calls the Messages API at version `2026-10-21`, with structured output (`output_config.format`) at low effort and no sampling settings, which that version refuses.
- 2026-10-23: The CoFID import keeps the first row of a food code listed twice (CoFID 2021 has one), and leaves out the 33 foods with no energy (spices), since they can't be logged. `--apply --local` writes to `.dev.db` for `npm run dev`.
- 2026-10-23: The green accent is "forest" (`#1D7A4C` light, `#6DD39C` dark), proposed in Stage 3 and held at the same contrast levels as Mateen Money's blue; "sage" and "teal" were offered beside it, for the user to pick. Changing it is a token edit in `styles.css` (and the theme-color metas, manifest and icon).
- 2026-10-23: Small rules set in Stage 3, for the user to overturn: quick-log chips are your foods logged in the last 90 days (saved meals join in Stage 4), most logged in the current meal slot first, up to 8; a quick-log tap logs at the usual portion, with Undo; a food's name keeps its own case in toasts ("Logged 40 g Porridge Oats to snacks."); short text (up to 4 words, no commas) searches as you type, a longer sentence waits for Check Items; changing the words clears the items read from them; To check rows show grams, ~kcal, meal and day, with Confirm beside each (tap the row to change the grams); confirming with new grams recalculates the entry from the same food.
- 2026-10-23: Until Stage 6, Settings holds only the backend connection and the daily target (kcal and protein, fixed mode, from today), so Log can be used; the other tabs say which stage builds them.
- 2026-10-23: The app icon is a plate seen from above, a white rim on the accent green, drawn by `scripts/make-icons.js` with no dependencies.
- 2026-10-23: Entries gain `savedMealId` (the saved meal an entry was logged from), so quick log can count a saved meal once each time it's logged however many foods it has. It's checked like every other reference, on writes and on restore. The D1 schema isn't deployed yet, so it's a plain column in `worker/schema.sql`; a database made before this needs `ALTER TABLE entries ADD COLUMN savedMealId TEXT` (or a fresh `.dev.db`).
- 2026-10-23: Small rules set in Stage 4, for the user to overturn: quick log shows batches made in the last 14 days with something left first (newest first), then your foods and saved meals together, most logged in the meal slot first; a saved meal never logged still shows, after the used ones; up to 8 chips in all. A batch chip opens the batch's sheet (grams on the number pad, or 1 to 4 portions as chips) rather than logging at once, since logging from a batch asks how much. A saved meal chip logs every food at its saved grams, with Undo. Portions logged are counted from each portion entry's grams over a portion's weight, and the next portions carry on from there, so the remainder still lands in the last. Making a recipe starts from the last batch's ingredients (the recipe's own the first time) and never changes the recipe; the pot comes off only when the dish is weighed. Typed nutrition takes up to one decimal for kcal and three for grams, a comma or a point; blank is unknown. Foods you add are `custom` and marked edited; changing an estimate's nutrition makes it your own food (no "~", assumptions cleared), renaming it doesn't. A deleted food still counts in saved meals and recipes that name it. My Foods searches only your foods; the sources are searched when adding to a meal or recipe. A saved meal's sheet offers "Log to Lunch", or "Save and Log to Lunch" once changed.
- 2026-10-23: Small rules set in Stage 5, for the user to overturn: Week and Month step back and forward with arrows (never past the current one); the view and the chart's range are kept while you move between tabs. A period's main figure is the average kcal of its complete days (today never counts), against the average of those days' targets; with none it says "No complete days yet." Protein days count the period's days up to today, today only once it's reached, so a day still being eaten never counts against you. Macros are meters against the target where one is set ("92 g of 120 g"), otherwise as a share of the kcal ("31 g, 28% of kcal"); a week's or month's are a complete day on average. Calories by meal and the top 5 foods are totals of everything logged in the period, To check included; foods are grouped by food, batch, or name for quick adds. The Today view's panel is kcal eaten against the day's target, with Health's active kcal and steps. Sync Health opens the Shortcut and shows when Health last sent activity. The weight chart's ranges are the last 30 days, the last 91 days and everything; its axis steps are 0.5, 1, 2 or 5 kg (1, 2, 5, 7 or 14 lb in st lb); weigh-in dots are `--ink-2` beside the trend line in `--ink`, with a tooltip for the nearest day and the same days as a table. Add Weight takes kg with one decimal (a comma or a point), or stones and pounds, and a date; a day's reading is replaced by saving that day again, and can be deleted with Undo. Meters are accent on an accent-soft track and stay full when over, with the words saying how far over (never red).
- 2026-10-23: Setting checks and defaults moved from the Worker into `src/engine/settings.js`, so Settings on the phone and the Worker refuse the same values with the same words.
- 2026-10-23: Small rules set in Stage 6, for the user to overturn: History shows days that have entries, newest first, 14 at a time, each with its state as a tag (today has none) and its total against its target; entries are grouped by meal. A search keeps only the entries that match, and hides the copy and mark buttons. Copy to Today works for one entry, a meal or a whole day; copies keep everything but their id, date and time logged, so a copied To check entry is still to check and a copied batch serving still comes off the batch; Undo removes them. Changing an entry's grams scales its own copied nutrition (rounded once), never its food's current figures, and makes the portion typed; saving a To check entry from History confirms it. Every edit, delete and mark has Undo. Settings: the goal and mode are chips; adaptive uses the maintenance estimate ± the goal rate once the estimate is ready (held at the floor), and the typed kcal until then; protein is needed, carbs and fat optional; the target saves from today with its button, and everything else saves as soon as it changes. Until the backend is connected, Settings shows only the backend, backup and the update check. The restore confirm names the backup's date and how many records it holds, deleted ones included.
- 2026-10-23: Manual exercise (an activity from `data/activities.json` and minutes, "~" kcal from MET values) is built in Stage 8, beside the Health sync (the user's choice). No stage had it.
- 2026-10-23: Small rules set in Stage 7, for the user to overturn: the review card shows on Log, under the headline, from the Monday after a week until that week is reviewed, and only when the week had something logged or weighed. The review is one sheet in three steps: the days (confirm To check, "Mark N Days Complete" for the unflagged unreviewed days, then "Was Tuesday complete?" for each flagged one), the week (the summary's figures and its top 5 foods), and the target. Adaptive proposes the maintenance estimate to the reviewed Sunday ± the goal rate, never below the floor. Fixed proposes a change from the trend against the goal (the gap at 7,700 kcal a kg, a day's worth), at most 150 kcal a week like the estimate, to the nearest 10 kcal, never below the floor; a gap under 50 kcal a day is "You're on track." and changes nothing. "Use" is picked to start; Done saves the review and any new target (from today) in one write, and the toast says how many weeks in a row.
- 2026-10-23: Manual exercise's MET values are from the 2024 Adult Compendium of Physical Activities (Herrmann et al., 2024), read from its tracking guide on pacompendium.com on 2026-10-23: 48 everyday activities in six kinds (walking, running, cycling, gym, sports, swimming), each keeping its 2024 code and description in `data/activities.json` so it can be checked. Names are plain ("Walk, brisk", "Weights, general"). A workout is added on Overview → Today with its kcal from the latest weight on or before that day, always "~"; it can't be added before a weight exists. Health's workouts show beside them and are changed in Health, not here.
- 2026-10-23: Small rules set in Stage 8, for the user to overturn: the weight history import goes through the API (the token from the environment, never an argument), keeps one reading a day (the latest), dates each by the offset it was weighed in, and never replaces a day that already has a reading, so running it again adds nothing. The Health Shortcut's workouts are optional, since active energy already counts them. `docs/shortcuts.md` is the setup for Sync Health (run by the morning alarm), Log Food (dictated, To check) and the Monday summary.
- 2026-10-23: Deployed (Stage 9). D1 `mateen-foodey` in Western Europe; the Worker at `https://mateen-foodey.mateen-money.workers.dev` (the account's workers.dev subdomain is named after Mateen Money), with preview URLs off; the app at `https://spowlf.github.io/mateen-foodey/`, served as is (`.nojekyll`). The API token was generated on the Mac and stored only in the macOS Keychain (service `mateen-foodey-api-token`) and as the Worker secret; it never went into the repo, a file or the chat. CoFID 2021 (2,853 foods) is imported into D1. The Anthropic and USDA keys are for the user to set with `npx wrangler secret put`, so they're never typed anywhere else; until then sentence and photo logging say the key is missing, and search leaves USDA out.
- 2026-10-23: Settings keeps the typed backend address and token on the phone (IndexedDB) until they connect, since iOS can reload a home screen app you switch away from to copy the token, which emptied the form and gave "Nothing changed: connect to your backend in Settings." Connect says which field is empty, and an address typed without https:// gets it.
- 2026-10-23: The token field in Settings isn't a password field (masked with CSS, with Show), because Safari's password AutoFill matches by site and both apps live on spowlf.github.io, so it offered Mateen Money's token and the backend refused it. Its hint gives the length and last 4 characters, to compare with the Mac's copy.
- 2026-10-23: Among foods that match a search equally closely, one named "whole" comes first (the user's choice), so "2 boiled eggs" finds "Eggs, chicken, whole, boiled", not the yolk that won before on its shorter name. It sits after the fewest extra words and before the most used.
