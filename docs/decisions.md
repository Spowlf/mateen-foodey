# Decisions

Dated decisions, many by the user's choice. Read the ones for an area before changing its behaviour or wording, and add new ones here. Do not undo one without asking.

- 2026-10-22: The app is built the way Mateen Money is: the same ground rules, three layers, sync model (one `rev` counter, soft deletes, `GET /sync?since=rev`), writing style, design principles and git rules. Mateen Money's files are copied in where HANDOVER.md section 7 says (styles.css, dom.js, idb.js, sw.js, app.js, the Worker setup and the service worker tests), never linked. Its decisions on the look carry over too: no spring or press-scale motion, a neutral raised shadow, no tab bar blur, one small-print size, segmented controls for view switches, text-style secondary buttons (its decision of 2026-10-01).
- 2026-10-22: Mateen Money's repo is `../Mateen Money` (not `../mateen-money`); it is read only. `reference/mateen-money-CLAUDE.md` is its CLAUDE.md as of today.
- 2026-10-22: Unlike Mateen Money, the Worker never works out "today", and has no time zone setting. The phone sends every date: entries carry the local date at logging, Shortcuts send the phone's date, and summary requests send the phone's timestamp with its offset.
- 2026-10-22: Unlike Mateen Money, the Worker calls an AI model: Claude Haiku 5.5 (`claude-haiku-5-5`) for sentence and photo logging (parse, then estimate for unmatched items only). The phone never calls it. A spending limit is also set in the Anthropic Console. The daily cap is below (2026-10-23).
- 2026-10-22: Food sources are Open Food Facts (barcodes and branded UK foods, with an identifying User-Agent), CoFID (imported once into D1 by `scripts/import-cofid.js`, which prints what it will import and needs `--apply`) and USDA FoodData Central. Looked-up foods are cached in D1 with `fetchedAt`.
- 2026-10-22: The app is called Mateen Foodey (the user's choice).
- 2026-10-22: Fixed mode adds back 50% of a day's exercise kcal by default, editable in Settings (the user's choice): Health's active energy tends to read high and MET figures are rough, so half errs on the side that won't disappoint.
- 2026-10-22: The accent is not Mateen Money's blue, so the two apps can be told apart at a glance (the user's choice). It keeps the blue palette's roles and contrast and isn't red or amber. A green is proposed in Stage 3, with swatches, for the user to pick.
- 2026-10-22: Body weight shows in kg by default ("72.4 kg"), with st lb as a setting (the user's choice).
- 2026-10-22: Dietary write-back to Apple Health is deferred to version two (the user's choice). Version one has no write-back Shortcut, no `writebacks` table and no `GET /day` or `POST /day/*` routes (`GET /day` only served write-back). The incoming Health Shortcut (`POST /health`: activity, steps, workouts, weight), Sync Health and the weight history import are unchanged. Version two's design is in SPEC.md, Later: each nutrient per date is claimed before writing, never retried automatically, and an unconfirmed write needs "Leave Incomplete" or "Retry Anyway" (which warns about a possible duplicate). Exactly-once delivery is not guaranteed.
- 2026-10-22: `~/Downloads/CLAUDE.md` (a generic website template: Tailwind from a CDN, web fonts, Windows Puppeteer paths) is ignored; this project's CLAUDE.md is followed instead (the user's choice).
- 2026-10-22: D1 is created in Western Europe, where the user is now (the user's choice). The user moves to the US in 2027 and to Singapore for good in 2028. Then the Worker gets `[placement]` beside the database, as in Mateen Money, so a request makes one long trip rather than one per query. Moving the database to Asia-Pacific is an export and import, if it's ever wanted.
- 2026-10-22: The Worker calls the Claude API with plain `fetch`, not the Anthropic SDK (the user's choice), so the project keeps no dependencies and `npm test` needs no install.
- 2026-10-22: The repo is `spowlf/mateen-foodey`, public like Mateen Money's (GitHub Pages needs it), pushed straight to `main`.
- 2026-10-22: Dictation is the iOS keyboard's own; the app builds no microphone feature. Barcodes are typed first; camera scanning comes later, with the decoder vendored into `vendor/` and served from our own origin.
- 2026-10-23: Every route needs the bearer token; there is no unauthenticated health check (`GET /ping` was dropped from the proposal). `PUT /:table/:id` rejects a body whose `id` differs from the URL's, so a row can never be saved under the wrong id.
- 2026-10-23: The cost guard allows 100 model calls a day, and every call counts: parse, estimate and the sentence Shortcut's (`POST /log`). Its day is the Worker's own UTC date, the one exception to "the phone decides the date". Why: it's a spending cap, not user data, so it follows the bill rather than where the phone is, and a wrong or changing phone date can't reset it. Check and increment are one atomic D1 statement (an upsert that only adds while under 100, returning the new count), so two calls at once can't both take the last one.
- 2026-10-23: The goal rate is stored only in `targets` (with the target it produced), not in settings, so there's one place for it.
- 2026-10-23: Search asks the Worker only after a pause in typing, not on every keystroke, and the Worker caches recent queries as well as the foods they found, to keep requests to Open Food Facts and USDA modest.
- 2026-10-23: The weekly review's one-tap answer is "Mark N Days Complete" (N = the reviewed week's unflagged unreviewed days, the real count), not "All 7 Complete", since some days may already be marked and flagged days are asked about one by one (see the Monday review entry below).
- 2026-10-23: Restore validates the whole backup file before writing anything (valid JSON, required fields, duplicate ids, references between foods, recipes, batches, pots and entries), then writes it in one D1 batch, which runs as one transaction. A rejected or failed restore leaves the database exactly as it was and says "Nothing changed: …".
- 2026-10-23: The weekly review is on Monday morning and covers the previous Monday to Sunday (the user's choice), unlike Mateen Money's Sunday review. The card shows on Log from Monday until completed; `reviews.id` is the Monday that starts the reviewed week. The summary Shortcut runs on Monday morning, and `GET /summary?date=` and `POST /summary { timestamp }` pick the week before the one the date falls in. "Mark N Days Complete" confirms the reviewed week's unflagged unreviewed days and shows the real count; flagged days (under 60% of their target) are asked about one by one ("Was Tuesday complete?").
- 2026-10-23: Until the maintenance estimate has its minimums, its message is built from the real state, showing each part only while it's needed: "Log 6 more complete days and add 2 more weigh-ins.", "Log 6 more complete days.", "Add 2 more weigh-ins." Once both are met, the estimate shows instead.
- 2026-10-23: A backup holds every row, deleted ones too (Mateen Money's held only live rows), so an entry whose food was later deleted still finds it and restore can check every reference.
- 2026-10-23: An entry's or batch's nutrition is stored in thousandths of a kcal and micrograms (agreed in the proposal), so logging a food never rounds; the one rounding before display is splitting a batch, with any remainder in the last portion. The trend weight is worked out from the readings each time and never stored, so it's kept as a fraction of a gram and rounded only for display.
- 2026-10-23: Small rules set in Stage 1, for the user to overturn: CoFID fibre is AOAC fibre (the UK label method), and blank when only NSP is given; "usual grams" is the last portion logged; quick add's untyped macros are unknown, not 0; meal slots start at 04:00 / 11:00 / 17:00 / 21:00, and before 04:00 is still snacks; a day exactly at 60% of its target isn't flagged ("under 60%"); each nutrient left unknown gets its own sentence ("Fibre unknown for 1 food.", then "Salt unknown for 1 food.") so two foods' gaps never read as one food's; the maintenance estimate's 150 kcal weekly cap chains back only through weeks that meet the minimums.
- 2026-10-23: Quick-log chip order (by use in the current meal slot) moves to Stage 3, since ordering saved meals needs to know which entries came from one.
